## 前置说明：两处与需求描述不符的实际情况

审计前先核实了页面清单，有两点需要先说清楚，否则后面的清单会指向不存在的页面。

**1. 没有独立的「设置页」。**
全站路由共 31 个，页面级模板 12 个，其中 `login` / `register` 是注册流程，`admin` 是管理员后台。
设置能力（主题切换、壁纸开关与皮肤、头像、账号信息）全部收在**顶栏的设置弹层**里，
由 `partials.html` 的 `setpanel` / `pm` / `wp-card` 三个弹层承载。
所以「设置页优化」在本报告中对应的是**顶栏弹层的可发现性与移动端体验**，不是独立页面。

**2. 「教材详情页」在当前首页布局下不是主入口。**
按上一轮已确认的定位，教材模块沉到学习主页最底部；教材详情页是**辅助查阅页**，
优化重点是「快速找到目标页」与「不干扰刷题主流程」，视觉权重应低于学习主页与刷题页。

### 关于第1 条的教训（值得单独立规）

这是本项目**反复踩的同一个坑**：给元素加了 `display:flex` 之后，作者样式（优先级 0,1,0）
会顶掉 UA 的 `[hidden]{display:none}`（同优先级），于是 `el.hidden = true` 失效。

项目已在 `.sheetscrim` / `.sb-modal-mask` / `.sb-toast` / `.fab` 四处踩过，这次在 `.tb-thumbs` 第五次踩到。
**我自己在给 `.tb-loading` 加骨架屏时也险些重蹈**——加完 `display:flex` 后立刻意识到，
补了 `.tb-loading[hidden]` 才继续。

已立测试 `TestUIHiddenAttrNotBroken` 守住这条规则。

## 1.4 动画规范化说明

需求要求统一到 0.2~0.3s ease。当前全站时长从 `.15s` 到 `.9s` 共 **16 种**、缓动 **6 种**。

本轮做法（受 append-only 约束，不逐处改既有声明）：
- 定义 `--dur:.25s` / `--dur-fast:.2s` / `--dur-slow:.3s` / `--ease:ease` 四个令牌
- 对**尚无过渡或时长越界**的元素补齐，引用令牌
- 明确豁免两类：开屏叙事动画（`.9s`）、骨架呼吸（1.4s 循环），均已在注释标明理由并配 reduced-motion 兜底

**遗留**：已存在的越界声明（`.15s`×6、`.24s`×3、`.26s`×3、`.4s`、`.7s`、`.8s`、`.9s`×2）未动。
逐处改动会与 append-only 约定冲突且 diff 过大，建议在方案 C 里随间距阶梯一起收口。

### 与原计划的三处偏差（都是查代码后主动修正的）

**1. 暗色令牌没有「复算 170 行旧补丁」—— 因为实测证明没必要**

| | ink/card | muted/card | muted/bg |
|---|---|---|---|
| 第一代 | 13.56 | 7.23 | 8.21 |
| 第二代 | 13.47 | 6.53 | 7.14 |

### 过程中发现并修掉的两个自造bug

1. **`html:not([data-theme="light"])` 一度被写到了 media query 之外** ——

2. **`sbBindModal` 一度定义在 `profile_modal` 之后**，

## 方案 C：精品增强方案

**改动范围**：前端彻底重构 + 引入设计令牌体系，可能触及少量业务代码
**优先级**：P1 → P2

**范围**
1. **建立设计令牌体系**（方案 B 的根因治理）
   - `:root` 令牌去重（`--radius` 声明两次、`--bg` 四次、`--shadow` 两代）
   - 定义 `--sp-1..--sp-8` 间距阶梯（4 的倍数，8 档），替换全部 27 种间距值
   - 圆角统一到 `--r-sm` / `--r-md` / `--r-lg`，替换 21 处绕过变量的 `10px`
   - 阴影统一到三档令牌
   - **一次性全量替换**，不再 append-only
2. **49 个 `@media` 合并为 4 个断点**（380 / 640 / 900 / 1200），
   消除 `520px` 反向用法、统一 `pointer:coarse` 判据与 `prefers-reduced-motion` 拼写
3. **动画全量收口**到 `--dur` 令牌，开屏与骨架动画列白名单并注明豁免理由
4. **z-index 层级令牌化**
5. 视差滚动、页面过渡等轻量动效（须配 reduced-motion）

**工作量**：7~10 天

**优点**
- 彻底消除设计债，后续维护成本最低
- 令牌体系让新页面有一致的基准，不会再回到"随手写数值"

**缺点**
- **风险最高**：一次性改 2400+ 行样式，必须分批灰度 +逐页目视回归，
  建议每批改动后跑一次 `go test ./...` 并人工过一遍 6 个主要页面
- append-only 约定会被打破（这次是主动的、需要说明理由的例外）
- 收益主要是「可维护性」，**用户可感知的改善不如方案 B 直接**
